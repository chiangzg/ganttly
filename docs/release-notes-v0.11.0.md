## 关键路径算法修复(#29 + #31)

### 1. 摘要任务把"工作量"当"工期"喂给算法(主犯)

汇总任务的工期是**子任务工期求和**(工作量概念),而它的时间跨度通常远小于这个和。旧算法却把摘要当成普通任务塞进路径计算——摘要工作量越大,项目结束日被虚推得越远。真实项目实测:某分组 18 个子任务工期求和 146 个工作日,真实跨度只有 46 天,算法据此把项目结束日推到三个多月后,**所有真实的最晚工作链都背上几十天幻影浮动、一条都不标红**;用户看到的红条是约束钉死的旧任务和一个"组内全不红"的红摘要条。

修复:**摘要任务退出路径计算**,只算叶子任务(里程碑视为叶子);摘要条的红由"是否包含关键叶子后代"派生——组内红则组红,组内无红则组不红。

### 2. 四种依赖类型被当 FS 算

UI 支持完成→开始(FS)/开始→开始(SS)/完成→完成(FF)/开始→完成(SF)四种前置关系,自动重排引擎也按四种语义正确维持排程,但关键路径算法从不读取依赖类型、一律按 FS 计算——两边自相矛盾。构造 `A(10天) ←SS+2天— B(2天)` 即可让路径整体反转:A 明明决定结束日,旧算法却判 B 关键。

修复:四种语义全部进入正/反向计算,工作日步进与调度引擎完全一致;反向推导按类型镜像,SS/SF 场景下前驱的截止上限封顶于项目结束日。

### 3. 手动拖期的任务被算法无视

旧算法里,有依赖的任务只看"前驱允许它什么时候开始",完全无视你实际把它拖到了哪——拖晚三周也不红。修复后采用与 MS Project 一致的"按实际排程锚定":**你画在哪天,算法就认哪天**——手动拖期的任务继续驱动项目结束日并标红;违约提前的仍被网络拉回(不奖励违约)。

### 一并调整

- 任务表"关键路径"快捷筛选与画布高亮改用**同一份计算**,此前两者输入不同、结果可能对不上
- 任务抽屉的依赖候选**不再出现摘要任务**;摘要任务的依赖区显示提示(存量摘要级依赖数据无损保留,只是不参与路径计算)
- 约束任务(必须完成于/不得晚于)浮动为零而恒红,是标准 CPM 语义,本版保留

## MCP:`search_resources` 新工具 + 三项修复(#23 + #27)

- **新工具 `search_resources`**:此前 11 个工具没有任何能列资源或按名查找的入口,"按人名查任务"链路缺最后一环(资源只能以 `resourceId` 引用)。现在支持项目内按资源**名称/角色**大小写不敏感子串搜索,返回 id、名称、角色、容量,打通"人名 → resourceId → 任务筛选"链路
- **`list_projects` 的 `query` 参数修复**:schema 和 SQL 层都支持按名称过滤,但 MCP handler 传的是空对象,参数被静默丢弃——现在如实透传
- **创建/更新任务按项目日历计算结束日期(#27)**:此前经 MCP 创建的任务会出现 `start=09-11、end=09-11、duration=5` 的自相矛盾数据。现在 `create` 按"开始日落非工作日向后吸附、工期按项目日历推 `end`、里程碑 start=end 且 duration=0"计算;`update` 改走带祖先汇总的任务更新,改开始/工期后 `end` 自动重算

## 资源视图三连修(#24 + #26)

- **角色/容量终于能用鼠标改了**:v0.8.0 资源栏重构后这两格只剩 F2 键盘入口(且不可发现)。现在**双击角色/容量单元格 = 行内编辑该字段**(提交/取消/校验完全复用既有状态机);双击姓名区域保持下钻语义不变
- **悬浮卡片排版修复**:负载明细卡片的标签列被 auto 表格压到"一个汉字宽"逐字竖排、长任务名画出卡片边界压在时间轴上——标签列 `nowrap`、卡片内约束溢出,恢复为整齐的两列表格
- **图例不再遮挡日期表头**:右上角负载图例下移,让出日期刻度

## 自定义颜色任务的进度段颜色(#25)

任务设置自定义颜色(红/橙等)后,条身跟随任务色,但条内"已完成进度段"仍是固定的主题蓝,红条配蓝进度十分割裂。现在进度段 = **任务色同色加深**(与关键路径任务"红条+深红进度"同一条规则);默认色任务保持主题蓝,零视觉变更。

## 保存/拖拽跳滚两连修(#22 + #28)

- **远端项目保存后视图跳回顶部**:保存成功后快照替换 `file` 时丢失了 live viewState,任务树和甘特图一起瞬跳到顶部(SSE 回推时还会再跳一次)。现在替换快照保留当前滚动位置等视图状态
- **拖拽排序时视图自动跳滚**:列表滚动到底部后拖拽排序,视图会 1.5 秒内自动冲到顶部、任务落到碰巧所在的行。根因是拖拽自动滚动的指针位置依赖 `mousemove`,而**原生拖拽期间浏览器完全不派发该事件**,指针坐标恒为 0、循环认定指针在视口上方而疯狂上翻——改由 `dragover` 事件驱动指针,行为与直觉一致(资源视图同款逻辑镜像修复)
