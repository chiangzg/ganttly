本文是编辑器交互优化的自包含交接文档。实现者应以本文描述的用户语义、优先级和验收标准为准，并结合仓库现有 Command、Canvas scene、Zustand store 和 Playwright 测试模式落地。本文不要求一次性完成全部内容，建议按末尾的 PR 拆分顺序逐步交付。

## 1. 背景与评审结论

本轮重点检查了项目中心、项目编辑器、任务视图、资源视图、任务抽屉、任务行拖拽、右键菜单、任务创建、负责人分配、Canvas 悬浮与键盘操作。

Playwright 使用一个新建本地项目完成了以下实际路径：

1. 创建空白项目。
2. 新建两个任务并修改工期、进度。
3. 创建资源“王强”并分配到任务“开发实现”。
4. 在任务表拖拽任务、打开右键菜单和任务抽屉。
5. 切换到资源视图并展开资源下的任务。
6. 在任务与资源 Canvas 上执行悬浮、点击和右键。
7. 测试 `Cmd/Ctrl+Z`、取消编辑、新建后定位等行为。

### 1.1 已确认的关键问题

- 新任务创建在当天，但甘特图可能仍停留在项目起始日期。实测任务位于 2026-07-31，画布停留在 2026 年 1 月，创建后右侧完全看不到任务条。
- 任务抽屉的字段会立即写入 store，点击“取消”只关闭抽屉，不会撤销刚才的修改。
- 任务行拖拽已经存在，但任意落点都会将任务变成目标任务的最后一个子任务，不支持前插或后插。
- 普通任务条没有悬浮详情；只有法定假日和启用基线对比时存在 Tooltip。
- 任务已分配负责人后，任务 Canvas 仍只显示任务名，无法直接判断负责人。
- 任务 Canvas 右键无响应；右键菜单只在左侧任务表生效。
- 任务与资源 Canvas 的鼠标光标始终接近默认状态，无法预判拖动、缩放、连线等操作。
- 资源 Canvas 的负载柱和展开后的任务条不支持点击选中、双击编辑或悬浮查看明细。
- 资源行的删除按钮会直接删除，任务删除却使用浏览器原生确认框，两者风险提示不一致。
- `Cmd/Ctrl+Z` 没有全局撤销效果；现有键盘操作依赖任务行获得焦点，且缺乏可发现性。
- 任务抽屉从页面顶部开始覆盖，遮挡右侧项目导航、工具栏和画布，布局语义不明确。
- 顶部右侧同时存在“新建项目/项目更多”和“新建任务/编辑更多”两组相似入口，作用域难以快速区分。

### 1.2 优先级定义

| 优先级 | 定义                                                           |
| ------ | -------------------------------------------------------------- |
| P0     | 会造成误解、误操作、数据信任问题，或阻断核心任务创建与编辑路径 |
| P1     | 高频核心体验缺失，明显影响任务、负责人和资源负载的理解与操作   |
| P2     | 提升专业用户的连续操作效率和大型项目可用性                     |
| P3     | 提升一致性、可发现性和产品完成度                               |

## 2. P0：必须优先修复

### 2.1 新建或选中任务后自动定位到任务条

#### 当前问题

`Toolbar.addRootTask()` 使用 `todayISO()` 创建任务，但不会同步更新 `scrollLeft`。新项目的 Canvas origin 可能从默认项目日期开始，因此新任务虽然已出现在左表，右侧任务条仍可能在数月之外。

#### 目标行为

- 新建任务后，左侧任务行和右侧任务条都必须进入可见区域。
- 双击搜索结果、从资源视图打开任务、粘贴任务后也复用同一定位逻辑。
- 定位属于导航状态，不进入 undo/redo 历史。
- 若任务已经完整可见，不移动视图，避免无意义跳动。

#### 大致实现方案

1. 新增统一的 `revealTask(taskId, options)` 导航函数或 hook。
2. 使用 `originDateFor()`、`dateToPixel()`、当前 zoom 和实际 Canvas viewport 计算横向可见范围。
3. 使用 `buildTree()`、`flattenVisible()` 和任务全局行索引计算纵向位置；必要时先展开任务的祖先。
4. 直接更新导航类 view state，不使用 `setViewStateCommand()`，避免污染撤销栈。
5. `Toolbar` 新建、`TaskTable` 新建同级、粘贴、搜索定位和资源视图双击统一调用该函数。

#### 主要影响模块

- `components/Toolbar.tsx`
- `components/TaskTable.tsx`
- `components/GanttCanvas.tsx` 或新增 editor navigation hook
- `engine/layout`、`engine/scene`

#### 验收标准

- 在项目起点与今天相差 6 个月以上时新建任务，任务条自动进入视口。
- 新建后任务条不会被任务抽屉完全遮挡。
- 已可见任务不发生明显横向跳动。
- 定位操作不会新增“视图变更”撤销记录。

### 2.2 修正任务抽屉的保存与取消语义

#### 当前问题

抽屉虽然维护 `draft`，但名称、日期、工期、进度等字段在 `onChange` 时立即 dispatch。资源分配、依赖和约束也直接写入项目数据。底部“取消”实际上只是关闭抽屉。

#### 目标行为

- 打开抽屉时创建完整草稿。
- 修改期间只更新草稿和本地校验状态。
- 点击“保存”后一次提交整次编辑。
- 点击“取消”、关闭按钮或按 `Escape` 时丢弃草稿。
- 一次保存对应一条 undo 记录；一次撤销恢复保存前的完整状态。

#### 大致实现方案

1. 将任务基础字段、assignments、dependencies、constraints 全部纳入同一个草稿模型。
2. 新增复合 command，例如 `updateTaskFromDraftCommand(before, after)`；调度字段变化时只在保存阶段执行一次 rollup/级联。
3. 保存前统一执行日期、里程碑、循环依赖、资源存在性和约束校验。
4. 未修改时禁用“保存”；存在非法字段时阻止保存并在字段附近显示错误。
5. 切换选中任务或关闭项目前，若草稿有修改，先提示保存或放弃。

#### 主要影响模块

- `components/TaskDrawer.tsx`
- `store/useProjectStore.ts`
- `lib/schedule.ts`、`lib/summary.ts`

#### 验收标准

- 修改名称后点击“取消”，任务名称保持原值。
- 同时修改名称、工期、负责人和依赖后点击“保存”，一次全部生效。
- 保存后按一次撤销，所有字段一起恢复。
- 连续输入任务名称不会为每个字符产生独立撤销记录。

### 2.3 完善任务行拖拽排序和层级调整

#### 当前问题

当前 `onDrop()` 无论鼠标落在目标行的哪个区域，都会执行“成为目标任务最后一个子任务”。用户无法通过鼠标将任务移动到目标前方、后方或同层其他位置，也没有插入线或层级预览。

#### 目标行为

- 目标行上部：插入目标之前。
- 目标行中部：成为目标的最后一个子任务。
- 目标行下部：插入目标之后。
- 拖拽过程中显示插入线、缩进层级和拖动任务摘要。
- 禁止拖入自身或自身后代。
- 靠近列表顶部/底部时自动滚动。
- `Escape` 可取消拖拽。

#### 大致实现方案

1. 定义统一落点类型：`before | inside | after`。
2. 在 `dragover` 中根据指针相对目标行的 Y 比例计算落点，并保存本地 drag preview state。
3. `before/after` 使用目标的 `parentId` 和 sibling order；`inside` 使用目标 id 和子任务末尾 order。
4. 统一归一化受影响 sibling 的 order，避免重复或跳号。
5. 最终写入继续复用或扩展 `moveTaskWithRollupCommand()`，保证移动与摘要 rollup 属于同一 undo command。
6. 增加拖拽句柄或至少在行 hover 时显示可拖动光标，避免整行“可点击”和“可拖拽”语义冲突。

#### 主要影响模块

- `components/TaskTable.tsx`
- `store/useProjectStore.ts`
- `engine/scene/tree.ts`
- `store/useViewStore.ts` 或 TaskTable 本地 drag preview state

#### 验收标准

- 覆盖同级上移、同级下移、跨父级、成为子任务四种路径。
- 五层任务树中移动后 WBS、`parentId`、`order` 正确。
- 不能将父任务拖入自身后代。
- 拖拽后撤销/重做能完整恢复层级和摘要任务日期。

### 2.4 统一删除保护和撤销反馈

#### 当前问题

- 资源行 `x` 直接删除，没有确认或影响说明。
- 任务删除使用 `window.confirm()`，视觉和键盘行为与应用其他弹窗不一致。
- 删除后没有明确、就近的撤销反馈。

#### 目标行为

- 所有删除均使用应用内确认组件，不再使用浏览器原生确认框。
- 父任务删除显示子任务数量；资源删除显示受影响的任务分配数量。
- 删除成功后显示短时 undo toast。
- 删除仍通过现有 Command 模式完成。

#### 大致实现方案

1. 复用项目中心已有 `ConfirmDialog` 的模式，抽取通用确认组件。
2. 删除前计算影响摘要：子任务数、依赖数或资源 assignments 数。
3. 删除资源时明确采用现有语义：删除资源并移除全部对应 assignments。
4. 新增全局 editor toast 区域，toast 中的“撤销”调用 store `undo()`。
5. 删除按钮避免常驻高风险位置；资源行可改为行尾更多菜单，或至少增加二次确认。

#### 验收标准

- 删除父任务前显示连带删除数量。
- 删除已分配资源前显示受影响任务数量。
- 删除后点击 toast“撤销”能恢复任务、资源和 assignments。
- 键盘可聚焦确认弹窗，`Escape` 关闭，焦点返回触发元素。

## 3. P1：核心高频体验

### 3.1 将新建任务入口放到任务列表附近

#### 当前问题

新建任务只在第二层工具栏最右侧。任务列表和任务视图的视觉焦点在页面左侧，连续录入时需要反复跨越整个窗口。

#### 目标行为

- 任务表底部提供固定的 `+ 新建任务`，与资源列表现有的 `+ 新增资源` 保持一致。
- 有选中任务时，默认在其后创建同级任务；无选中任务时，在根任务末尾创建。
- 入口附带菜单，可显式选择“新建子任务”或“新建根任务”。
- 工具栏入口暂时保留，避免破坏已有操作习惯。

#### 大致实现方案

1. 抽取任务默认值构造函数，消除 `Toolbar` 与 `TaskTable` 中重复的 Task 初始化代码。
2. 新增 `createTaskRelativeToSelection(mode)`，统一处理 root/sibling/child 的 `parentId` 和 order。
3. 创建后进入任务名行内编辑或将抽屉名称字段自动聚焦，同时调用 `revealTask()`。
4. 当处于资源视图时，工具栏“新建任务”应明确说明会创建任务，或将其放入视图相关菜单，避免与“新增资源”竞争。

#### 验收标准

- 用户在任务列表附近可一键连续创建同级任务。
- 新建子任务、根任务和同级任务的位置正确。
- 新建后名称输入自动聚焦，任务条同时可见。

### 3.2 普通任务条悬浮详情

#### 当前问题

普通模式下悬浮任务条没有 Tooltip。现有 `useBaselineHover` 只在基线对比开启时工作，`useHolidayHover` 只处理法定假日。

#### 目标行为

任务 Tooltip 至少显示：

- WBS 和任务名称。
- 负责人。
- 开始、结束和工期。
- 进度。
- 前置/后置任务数量。
- 约束或冲突状态。
- 基线开启时，在同一 Tooltip 追加基线偏差，不显示两个重叠 Tooltip。

#### 大致实现方案

1. 新增 `useTaskHover()`，使用现有 `hitTest()` 找到任务条。
2. 将普通任务详情与基线详情合并为一个 task hover model。
3. Tooltip 优先级固定为：任务条 > 法定假日；基线信息是任务 Tooltip 的一部分。
4. 仅在 idle 状态显示，拖动、缩放、连线和画布平移时隐藏。
5. 延迟约 300ms，位置限制在 Canvas viewport 内，避免右边缘溢出。

#### 主要影响模块

- `components/GanttCanvas.tsx`
- `components/useBaselineHover.tsx` 或新的统一 hover hook
- `engine/interaction/index.ts`
- `engine/render/types.ts`

#### 验收标准

- 普通任务、摘要任务、里程碑都能显示正确详情。
- 基线开启时只显示一个合并 Tooltip。
- 法定假日与任务条重叠时优先显示任务详情。
- Tooltip 在左右边缘和抽屉打开时不越界。

### 3.3 在任务甘特图直接显示负责人

#### 当前问题

任务已有 `assignments`，但 `TaskRow` scene 不携带资源名称，Canvas 标签只绘制 `row.name`。实测“开发实现”已分配“王强”，任务条旁仍只显示“开发实现”。

#### 目标行为

- 单负责人：`开发实现 · 王强`。
- 多负责人：`开发实现 · 王强 +2`。
- 未分配：显示弱化的“未分配”。
- Tooltip 展示全部负责人及各自投入比例。
- 标签过长时优先保留任务名，负责人摘要可以截断，但完整信息必须可通过悬浮获得。

#### 大致实现方案

1. 扩展 `TaskRow`，增加 `assignees` 或 `assignmentSummary`。
2. `assembleScene()` 预先构建 `resourceId -> Resource` map，避免每行嵌套查找。
3. `drawRowLabel()` 组合任务名和负责人摘要，并沿用现有 ellipsis 逻辑。
4. assignment 数组顺序作为首要负责人顺序；首版不新增独立 owner 字段。

#### 验收标准

- 单人、多人、未分配三种状态均可识别。
- 删除资源或取消分配后标签立即更新。
- 1000 任务场景保持 O(n) scene 装配，不在 render loop 内执行资源数组查找。

### 3.4 补齐任务 Canvas 的右键、光标和焦点操作

#### 当前问题

- 任务 Canvas 没有 `onContextMenu`，右键任务条无响应。
- Canvas 光标不会根据 body、左右手柄、连线边缘切换。
- Canvas 没有清晰的键盘焦点和选中后操作路径。

#### 目标行为

- 右键任务条打开与左表一致的任务菜单。
- body 使用移动光标，左右边缘使用 resize 光标，连线点使用 crosshair/alias 类光标，空白拖动使用 grab/grabbing。
- Canvas 可聚焦；选中任务后支持 `Enter` 打开抽屉、`Delete` 删除、`Escape` 清除选择。
- 右键菜单支持 `Escape` 关闭，并将焦点返回原任务。

#### 大致实现方案

1. 在 Canvas `onContextMenu` 中执行 hit test，并调用现有 `openContextMenu(taskId, x, y)`。
2. 在 idle pointer move 中记录当前 hit kind，仅用于 cursor/hover，不进入项目 store。
3. 为 Canvas 设置 `tabIndex=0` 和明确的 aria-label。
4. ContextMenu 菜单项增加“上移/下移”，并显示已有快捷键提示。

#### 验收标准

- 左表和 Canvas 对同一任务展示一致的右键操作。
- 各命中区域光标正确，拖动过程中状态稳定。
- 键盘可以完整完成选择、打开、删除和取消选择。

### 3.5 资源视图负载悬浮详情

#### 当前问题

资源 Canvas 只复用了法定假日 Tooltip，负载柱和展开任务条没有明细。

#### 目标行为

- 资源汇总行悬浮某天：资源名、日期、实际负载、容量、是否超载、贡献任务列表。
- 展开任务条：任务名、日期范围、该资源投入比例、人天和进度。
- 红色超载状态给出明确数值，而不是仅靠颜色判断。

#### 大致实现方案

1. 新增 `hitTestResourceScene(scene, x, y)`，返回 resource/day、task lane 或 empty。
2. 扩展资源 scene，让某天负载能够追溯贡献任务；可以在 scene assembly 中预计算，避免 Tooltip 临时全量扫描。
3. 新增 `useResourceHover()`，Tooltip 定位与 `useHolidayHover()` 使用相同边界策略。
4. Tooltip 优先级：资源负载/任务条 > 法定假日。

#### 验收标准

- 正常负载、超载、零容量和多人任务均显示正确数值。
- Tooltip 内容与左侧容量、任务抽屉 assignment 一致。
- 不只依赖红/绿颜色表达超载。

### 3.6 资源 Canvas 支持选择和打开详情

#### 当前问题

点击资源负载柱或展开后的任务条不会选中任何内容，也不能打开任务抽屉。用户必须回到左表操作。

#### 目标行为

- 单击资源汇总行或负载柱，同步选中左侧资源。
- 单击展开任务条，同步选中左侧任务 lane。
- 双击任务条打开任务抽屉。
- 点击空白清除当前选择；拖动超过阈值仍执行画布平移。

#### 大致实现方案

1. 复用 3.5 的 resource hit test。
2. 保留现有 pan threshold：pointer down 后未超过阈值才按 click 处理。
3. 任务双击时同时更新 `selectedTaskIdInResource` 和 `file.viewState.selectedTaskId`，再打开抽屉。
4. 资源选择继续放 `useViewStore`，不进入 undo 栈。

#### 验收标准

- 左右两侧选择高亮始终同步。
- 点击与拖动平移不会互相误触。
- 双击任务条打开正确任务，关闭后资源视图选择仍保留。

### 3.7 将任务抽屉改为编辑器内检查器

#### 当前问题

当前抽屉使用 `absolute top-0 right-0 h-full`，会覆盖项目导航、第二层工具栏和画布。抽屉又没有模态遮罩，左表仍能继续操作，整体既不像模态框，也不像并排属性检查器。

#### 目标行为

- 抽屉位于两层导航下方，只占编辑器内容区。
- 打开抽屉时主画布重新计算可用宽度，不被遮挡。
- 默认宽度约 360px，支持 320-480px 调整。
- 基础信息优先展示：名称、负责人、日期、工期、进度。
- 依赖、约束、加班日、备注等放入可折叠高级区域。

#### 大致实现方案

1. 将 Drawer 放入 `GanttView` 主内容 flex 布局，而不是页面级 absolute overlay。
2. 抽屉宽度作为 UI preference 保存，不进入 undo 栈。
3. 通过 ResizeObserver 触发 Canvas 重新测量；打开后调用 `revealTask()` 保持选中任务可见。
4. 结合 2.2 的草稿语义增加 sticky footer：删除、取消、保存。

#### 验收标准

- 抽屉打开时项目导航、工具栏均可见。
- Canvas 与左表不发生错位，横向滚动范围正确更新。
- 选中任务不会被抽屉完全遮挡。
- 1192 x 955 和 1440 x 900 下无重叠。

## 4. P2：专业操作效率

### 4.1 支持左右面板宽度与关键列宽调整

#### 当前问题

任务表固定 480px，资源表固定 420px。任务名称较长或资源信息较多时只能截断，用户不能按当前工作内容分配空间。

#### 大致实现方案

- 在左表与 Canvas 之间增加拖动分隔线，任务表建议限制在 320-720px，资源表限制在 300-640px。
- 表头列分隔线支持调整任务名、负责人等关键列。
- 布局偏好写入 localStorage，以 project id 作为 key；不要进入项目 Command 或 JSON 导出。
- 双击分隔线恢复默认宽度。

#### 验收标准

- 拖动过程左右表与 Canvas 行保持对齐。
- 刷新页面后恢复宽度。
- 极限宽度下文本不覆盖相邻列。

### 4.2 补齐全局快捷键和快捷键提示

#### 当前问题

现有快捷键主要绑定在任务行 `onKeyDown`。Playwright 实测 `Cmd/Ctrl+Z` 不会触发项目撤销；右键菜单也不显示快捷键。

#### 大致实现方案

1. 新增 `useEditorShortcuts()`，挂载在 `GanttView`。
2. 支持：
   - `Cmd/Ctrl+Z`：撤销。
   - `Shift+Cmd/Ctrl+Z` 或 `Ctrl+Y`：重做。
   - `Cmd/Ctrl+S`：保存。
   - `Enter`：任务行聚焦时新建同级任务。
   - `Alt+Up/Down`：上下移动。
   - `F2`：重命名。
   - `Delete`：任务表或 Canvas 聚焦时删除选中任务。
3. 输入框、textarea、select、contenteditable 聚焦时，不拦截文本编辑快捷键；保存快捷键除外。
4. 在右键菜单和按钮 tooltip 中显示快捷键。

#### 验收标准

- Windows/Linux/macOS 键位均有测试。
- 输入任务名称时 `Delete` 和撤销只影响输入内容，不误删任务或撤销项目。
- 全局撤销和工具栏撤销行为一致。

### 4.3 表格快速编辑

#### 当前问题

任务表只有 `F2` 名称编辑，工期、进度和负责人必须进入抽屉，连续维护大量任务成本较高。

#### 大致实现方案

- 双击名称、工期、进度、负责人单元格进入行内编辑。
- `Enter` 提交，`Escape` 取消，`Tab` 提交并进入下一可编辑单元格。
- 每次单元格提交只生成一条 command；日期/工期变化继续走 rollup 和级联路径。
- 摘要任务的不可编辑字段继续禁用，并通过 tooltip 解释原因。

#### 验收标准

- 名称、工期、进度和负责人都能通过键盘连续录入。
- 取消编辑不修改数据。
- 摘要任务和里程碑遵守现有字段约束。

### 4.4 查找、筛选和任务定位

#### 当前问题

编辑器没有任务查找或筛选。任务超过几十条后，定位负责人、未分配任务或延期任务需要手动滚动。

#### 大致实现方案

- 在任务表上方增加紧凑搜索入口，不增加新的页面级营销式区域。
- 支持任务名/WBS 搜索，以及负责人、未分配、关键路径、延期状态筛选。
- 搜索结果选中后展开全部祖先并调用 `revealTask()`。
- 首版筛选只影响显示，不改任务层级和持久化数据；筛选状态放 `useViewStore`。

#### 验收标准

- 搜索折叠层级中的任务时能自动展开并定位。
- 清除筛选后恢复原折叠状态或采用文档化的一致策略。
- 筛选状态不进入 undo 栈。

### 4.5 时间轴导航增强

#### 当前问题

当前只有今天和离散缩放。新建定位、适应项目范围、缩放锚点等行为不完整。

#### 大致实现方案

- 增加“适应项目范围”按钮，按当前可见任务的起止日期计算 zoom 和 scrollLeft。
- 工具栏缩放以 Canvas 中心或选中任务为锚点；`Ctrl/Cmd+wheel` 以鼠标日期为锚点。
- 任务/资源视图继续共享横向时间位置。
- 今天、适应项目、reveal task 都复用统一的时间轴导航 helper。

#### 验收标准

- 缩放前后锚点日期在屏幕上的位置基本不变。
- 适应项目范围后最早和最晚任务均可见，并留合理边距。
- 切换视图不丢失时间上下文。

### 4.6 多选与批量操作

#### 当前问题

当前只支持单任务选择，大型项目中批量分配负责人、设置进度或移动任务效率低。

#### 大致实现方案

- `Cmd/Ctrl+Click` 增减选择，`Shift+Click` 选择连续可见范围。
- 批量操作栏支持负责人分配、进度调整、移动和删除。
- Canvas 与任务表共享 selection set；主选中任务继续用于抽屉。
- 批量修改必须封装为单个复合 command。

#### 验收标准

- 多选在折叠、筛选和滚动后保持一致。
- 一次撤销恢复整个批量操作。
- 删除父子任务同时被选中时避免重复计数和重复删除。

## 5. P3：一致性与可发现性

### 5.1 梳理顶部两层工具栏的操作作用域

#### 当前问题

第一层右侧是“新建项目 + 项目更多”，第二层右侧是“新建任务 + 编辑更多”。相邻的加号和省略号外观接近，用户需要依赖 tooltip 才能判断作用域。

#### 大致实现方案

- 第一层只保留项目切换、项目标签和项目级菜单。
- 将任务创建主入口移动到任务列表附近后，第二层右侧只保留撤销、重做、保存和导出等编辑器操作。
- 菜单内增加清晰分组标题，例如“项目操作”“当前计划”“导出”。
- 资源视图中隐藏或禁用无关任务视图控制时，避免留下过多不可用按钮。

#### 验收标准

- 不依赖 tooltip 也能从位置和标签判断操作作用域。
- 1024-1440px 宽度下主要操作不发生挤压或文本溢出。

### 5.2 完善任务和资源空状态

#### 当前问题

零任务时左表和 Canvas 大面积空白，唯一创建入口仍在远端工具栏。零资源时虽有底部新增按钮，但右侧没有说明当前状态。

#### 大致实现方案

- 零任务时在任务表内容区显示一个明确的“新建首个任务”入口，同时保留时间轴作为项目背景。
- 零资源时在资源表显示“新增资源”，右侧负载图保持空状态但不伪造示例数据。
- 空状态消失后不保留说明性占位内容。

#### 验收标准

- 新用户无需移动到页面右上角即可创建首个任务或资源。
- 空状态在亮色、暗色主题和窄视口下均不遮挡工具栏。

### 5.3 增加资源负载图例和容量单位

#### 当前问题

资源视图使用绿色、红色和容量线表达负载，但页面没有图例；容量输入显示裸数字 `100`，没有 `%` 单位。

#### 大致实现方案

- 在资源表头或状态栏增加紧凑图例：容量内、超载、容量线。
- 容量编辑显示 `%` 单位，内部仍保存为 0-1。
- 红色超载同时通过文本、图标或 Tooltip 数值表达，满足非颜色识别。
- 容量为 0、兼职容量和负载超过 100% 时显示一致。

#### 验收标准

- 用户能直接理解绿色、红色和虚线/容量线的含义。
- 50% 容量、60% 负载明确显示为超载。
- 暗色主题下图例与 Canvas 颜色一致。

### 5.4 统一上下文菜单的关闭和禁用状态

#### 当前问题

Playwright 实测右键菜单无法通过 `Escape` 关闭，只能点击遮罩。升级/降级等不适用操作仍可能以可点击状态出现，执行后只是关闭菜单。

#### 大致实现方案

- 使用 Radix ContextMenu 或补齐现有菜单的焦点管理、方向键、`Escape`、点击外部关闭。
- 根据任务位置预先禁用“上移、下移、升级、降级”。
- 菜单位置限制在 viewport 内，靠近右下角时自动翻转。
- 菜单关闭后焦点返回触发任务行或 Canvas。

#### 验收标准

- 菜单可用方向键导航，`Enter` 执行，`Escape` 关闭。
- 不可执行操作有明确 disabled 状态，不产生空操作。
- 右下角任务打开菜单时不越出屏幕。

## 6. 内部接口与数据流建议

以下为内部接口建议，不要求修改对外 JSON schema，除非实现者选择将布局偏好持久化到项目文件。默认方案是布局偏好使用 localStorage。

### 6.1 Task scene 扩展

建议扩展 `TaskRow`：

```ts
interface TaskRow {
  // existing fields...
  assignees: Array<{
    resourceId: string;
    name: string;
    load: number;
  }>;
  predecessorCount: number;
  successorCount: number;
}
```

scene assembly 应预建 resource map 和 successor count map，保持 O(n)。Canvas renderer 和 hover hook 只消费 scene，不直接访问 store。

### 6.2 统一命中结果

任务 Canvas 可继续使用现有 hit kind，但建议让 hover、cursor、context menu 和 pointer down 共享同一命中结果。

资源 Canvas 建议新增：

```ts
type ResourceHit =
  | { kind: 'empty' }
  | { kind: 'resource-day'; resourceId: string; date: string }
  | { kind: 'task-lane'; resourceId: string; taskId: string };
```

### 6.3 任务拖拽落点

```ts
type TaskDropPosition = 'before' | 'inside' | 'after';

interface TaskDropTarget {
  taskId: string;
  position: TaskDropPosition;
  parentId: string | null;
  order: number;
}
```

落点预览属于 ephemeral UI state，不应写入项目文件或 undo 栈。

### 6.4 编辑器导航 helper

统一处理以下命令：

- `revealTask(taskId)`。
- `jumpToToday()`。
- `fitProjectRange()`。
- `zoomAround(anchorDate, nextZoom)`。

导航直接更新 view state，不能通过结构性 Command 写入 undo 栈。

### 6.5 抽屉复合保存

抽屉保存应生成一条 command。若任务日期或依赖导致 successor 级联，command 必须捕获全部被修改任务，使一次 undo 能恢复完整状态。不要通过连续 dispatch 多个 command 模拟一次保存。

## 9. 明确假设与非目标

### 9.1 默认假设

- 首轮以桌面端鼠标、触控板和键盘为主，不单独设计移动端任务编辑器。
- “负责人”继续由现有 `Task.assignments` 推导，不新增单独 owner 字段。
- assignments 数组第一项作为标签中的首要负责人，多人显示 `+N`。
- 布局宽度是用户偏好，不属于项目业务数据，默认使用 localStorage 持久化。
- 任务/资源 hover 使用 DOM Tooltip，Canvas 只负责绘图与 hit test。
- 导航、选择、hover、拖拽预览和筛选不进入 undo 栈。

### 9.2 本轮非目标

- 不修改固定工期的人天计算模型。
- 不新增服务端协作、权限或远程同步。
- 不重做整体视觉品牌或项目中心信息架构。
- 不将 Canvas 改写为 SVG/DOM。
- 不在本轮引入新的独立 owner schema 或资源日历。

## 10. 完成定义

单个修复项只有同时满足以下条件才算完成：

1. 目标交互可通过鼠标和适用的键盘路径完成。
2. Command/undo 语义正确，导航类状态不污染撤销历史。
3. 亮色、暗色和目标桌面视口没有遮挡、错位或文本溢出。
4. 新增或更新对应 unit/E2E 测试。
5. 不破坏现有任务拖动排期、依赖级联、摘要 rollup、基线和资源负载计算。
6. Playwright 真实操作验证通过，不仅依赖静态截图或代码检查。
