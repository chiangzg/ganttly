## 1. 背景与目标

ganttly 的任务目前只能用日期、依赖、关键路径表达轻重缓急，回答不了"这件事现在有多要紧、多重要"。四象限（艾森豪威尔矩阵）用"重要 × 紧急"两个维度把任务分成四类，帮助用户决定先做什么、计划做什么、授权什么、少做什么。

### 1.1 产品目标

1. 任务上新增可选的优先级字段（四档，对应四个象限），随项目文件同步。
2. 新增"四象限"视图：与任务视图、资源视图同构（左侧任务树 + 右侧内容区），右侧是"待分级托盘 + 2×2 象限"。
3. 优先级可在三处标记：拖拽卡片（四象限视图）、抽屉分段控件、右键菜单。
4. 标记结果在任务视图可见：任务树 P 标签、甘特条左端色条、悬浮提示。
5. MCP 客户端可读、写、查优先级。

### 1.2 成功标准

- 把一张卡片从托盘拖进象限即完成分级，⌘Z 一步撤销。
- 一次操作（一次拖拽 / 一次菜单选择 / 一次抽屉保存）= 一条撤销记录；值没变不产生记录。
- 刷新、远端同步往返后优先级不丢失（经 `normalizeFile` 与服务端 PUT 均保留）。
- 亮色、暗色下象限色与状态文字均可读；状态不只靠颜色表达。
- 现有任务视图 / 资源视图的行为与 e2e 不回归。

### 1.3 用户确认的决策

| 决策点     | 结论                                                                             |
| ---------- | -------------------------------------------------------------------------------- |
| 归类依据   | **手动四档优先级**。紧急度只在卡片上做日期提示，不按日期自动改归类               |
| 优先级归属 | **任务属性，项目共享**。不按用户各存一份                                         |
| 未分级任务 | 顶部**「待分级」托盘**，拖进象限即分级                                           |
| 视图布局   | **左侧任务树 + 右侧矩阵**，与任务视图、资源视图的结构统一（效果图 `split.html`） |
| 卡片密度   | 紧凑单行                                                                         |
| 其它视图   | 轻量露出：任务树 P 标签 + 甘特条色条 + 悬浮提示一行                              |

未采用"日期 = 紧急度"的自动规则：拖卡片会改任务日期并触发依赖、工期重排，象限还会随时间漂移。

### 1.4 明确非目标

- 不按日期自动推导紧急度，不让象限随时间自动迁移。
- 不按用户保存优先级；不提供自定义象限规则、名称、顺序。
- 摘要任务不参与分级（§2.3）。
- 首版不做：多选整组拖拽与批量设优先级（需要新增批量命令，见 §7 PR 4）；里程碑的画布色条；按优先级排序或筛选任务树；任务树独立"优先级"列；`.gan` 导入映射。
- 不新增只读 / 权限态（应用当前没有这类状态）。

## 2. 核心模型（§2）

### 2.1 优先级字段

`Task.priority?: TaskPriority`，其中 `TaskPriority = 1 | 2 | 3 | 4`。**键不存在 = 未分级。**

| 值  | 标签   | 含义         | 行动提示         | 象限位置 | 颜色 token           |
| --- | ------ | ------------ | ---------------- | -------- | -------------------- |
| 1   | P1     | 紧急且重要   | 立即做           | 左上     | `--color-priority-1` |
| 2   | P2     | 重要不紧急   | 计划做           | 右上     | `--color-priority-2` |
| 3   | P3     | 紧急不重要   | 授权做           | 左下     | `--color-priority-3` |
| 4   | P4     | 不紧急不重要 | 少做             | 右下     | `--color-priority-4` |
| —   | 未分级 | 尚未判断     | 拖入象限完成分级 | 顶部托盘 | 中性                 |

轴：横轴从左（紧急）到右（不紧急），纵轴从上（重要）到下（不重要）。

不变量：

- `priority` 只取 1–4，或不存在。`normalizeFile` 在加载时丢弃越界值（§6）。
- 不物化默认值：新建任务与旧文件加载都不写 `priority` 键。
- 清除优先级 = 让键不存在（写入 `undefined`，序列化时自然省略）。

### 2.2 归类与日期提示

归类只由 `priority` 决定。日期只用于卡片上的文字提示，不改变归类：

| 提示 | 条件                                                            | 文案                                | 颜色           |
| ---- | --------------------------------------------------------------- | ----------------------------------- | -------------- |
| 逾期 | `progress < 100 && end < today`                                 | 逾期 N 天（N = 自然日）             | `text-danger`  |
| 临期 | 未完成、`end >= today`、`durationBetween(today, end, cal) <= 3` | 今天到期 / N 天后到期（N = 工作日） | `text-warning` |
| 完成 | `progress >= 100`                                               | 已完成                              | 中性           |
| 其它 | —                                                               | `MM-DD`                             | 中性           |

`today` 取现有 `todayISO()`；逾期判定与任务树的"延期"筛选同式。工作日按项目日历计算（与工期语义一致）。

### 2.3 显示范围

- 进入矩阵的：叶子任务与里程碑。
- **摘要任务不进矩阵，也不能在界面里设置优先级**，与现有筛选、批量分配、画布拖拽对摘要任务的处理一致。数据里残留的优先级不显示、不报错。
- 已完成任务默认不进矩阵；开启「显示已完成」后进入，置灰并排在所在桶的末尾。
- 任务树的搜索框（`searchQuery`）同时过滤矩阵。任务树的快捷筛选（未分配 / 关键路径 / 延期）只作用于任务树。

### 2.4 MCP 契约

- `create_task` / `create_tasks`：可选 `priority`（1–4）。
- `update_task`：可选 `priority`（1–4，或 `null` 表示清除）。
- `search_tasks`：可选 `priority`（1–4，或 `null` 表示只查未分级）；每条结果带 `priority`（未分级为 `null`）。
- `get_task` 返回完整任务，自然带 `priority`。

## 3. 标记入口与露出（§3）

### 3.1 抽屉

- 位置：「基本信息」分区，名称下方。
- 控件：`role="radiogroup"` 的五个分段按钮——未分级 / P1 / P2 / P3 / P4。选中段使用象限色（未分级用中性色）。
- 控件下一行说明当前选择的含义，例如"P1 · 紧急且重要 — 立即做"；未分级时为"任务会出现在四象限视图的「待分级」托盘里"。
- 语义：**草稿**。只有点「保存」才写入；一次保存 = 一条撤销记录；只改优先级时保存按钮可用。
- 摘要任务：不显示分段控件，改为说明"摘要任务不设优先级，请给具体子任务分级"。
- 用 `<button>` 实现，不引入 `<input>`——现有 e2e 按位置取抽屉里的 `input`（第一个是名称框）。

### 3.2 右键菜单

- 任务菜单在"转为里程碑 / 转为任务"之后新增「优先级」，右侧显示当前值（`P1 ›` 或 `未分级 ›`）。
- 点击后菜单**原位切换为二级页**：首项「← 优先级」返回，其后五个选项，当前项带勾选。
- 选择立即生效（`updateTaskCommand`，不触发汇总重算），一条撤销记录；值没变则不派发。
- 摘要任务：该项可见但禁用（不适用的操作可见地禁用，不做静默空操作）。
- 键盘：↑ / ↓ / Enter / Esc 与现有菜单一致；焦点在「优先级」项上按 → 打开二级页，二级页里按 ← 返回。
- ↑ / ↓ 按"可用项内的序号"移动。原先用的是全量序号，前面有禁用项时会跳过一项；本次一并修正。

### 3.3 任务树

名称之后显示 `P1`–`P4` 小标签，写法同「N 项」徽标（`shrink-0`，不挤占其它列）。仅已分级的叶子任务与里程碑显示；未分级的行没有任何占位。

### 3.4 甘特条

任务条左端内侧画一条 3px 宽、与条等高的象限色竖条。关键路径开启时条体变红、竖条照画；基线对比模式（条高 16px）照画。摘要条与里程碑首版不画。

### 3.5 悬浮提示

`TaskTooltip` 在"负责人"行之前增加「优先级」行，仅已分级时显示，格式"P1 紧急且重要"。

### 3.6 CSV 导出

在末尾追加「优先级」列，值为 `P1`–`P4`，未分级留空。

## 4. 四象限视图 · 交互（§4）

### 4.1 入口与布局

- `ViewMode` 增加 `'priority'`。工具栏的视图切换变为三段：任务视图 / 资源视图 / 四象限（图标 `LayoutGrid`）。**1024px 以下第三段只显示图标**（保留 `aria-label`），保证工具栏不横向溢出。
- 布局与任务 / 资源视图同构：`<TaskTable /><PriorityMatrix /><TaskDrawer />`。任务树保留搜索栏、筛选、新建任务与全部交互；抽屉仍是停靠的第三个弹性子元素。
- 此视图下工具栏**隐藏「日期导航」与「计划显示」两组**。它们只作用于甘特画布，没有画布时点击会按假定的 800×600 视口改写滚动位置。

### 4.2 结构

自上而下：

1. **视图条**（36px）。左侧汇总"已分级 N · 待分级 M"（有筛选时为"筛选后 N / 总数"）；右侧为负责人下拉（全部负责人 / 未分配 / 各资源）与「显示已完成」开关。
2. **待分级托盘**。
3. **2×2 象限网格**。上方轴标签"紧急 / 不紧急"，左侧竖排"重要 / 不重要"。

### 4.3 分桶与排序

- 桶：托盘（未分级）与 P1–P4。
- 托盘固定按 WBS 顺序排列。
- 象限默认排序：逾期优先 → 结束日期升序 → WBS。象限头部的排序按钮可切换为：默认 / 结束日期 / 开始日期 / 进度（低 → 高）/ WBS 顺序。各象限独立记忆。
- 已完成任务永远排在所在桶的末尾。

### 4.4 选择

- 按下卡片即选择，语义与任务树、画布一致（`computeSelectionOnPointerDown`）：单击替换、Ctrl/⌘ 切换、Shift 按"当前渲染的卡片顺序"连选（托盘在前，其后 P1–P4）。
- 与任务树共享选中集合：
  - 树里选行 → 对应卡片高亮并滚动到可见。
  - 点卡片 → 任务树展开其折叠的祖先并滚动到该行。只做纵向定位，**不改甘特图的横向滚动位置**。
- 点击象限或托盘的空白处清空选择；Esc 清空选择。

### 4.5 拖拽分级

- 整张卡片可拖。矩阵的主操作就是拖，这一点与任务树"仅把手可拖"有意不同。
- 落点是四个象限与托盘，整个区域（含标题带）都算。悬停时落点高亮、源卡片变淡，Esc 取消。
- 松手：目标是象限 → `updateTaskCommand(id, { priority })`；目标是托盘 → 清除优先级；值没变 → 不派发（`dispatch` 对空操作也会压一条撤销记录）。
- **首版只移动被拖的那一张。** 拖动多选成员之一时，选择先收敛为该卡片；整组移动需要批量命令（§7 PR 4）。
- 落点成功后选中该卡片，任务树随之定位。
- 任务树把手的拖拽经过矩阵时矩阵不响应；矩阵卡片拖到任务树上时任务树也不响应（任务树只接受自己发起的拖拽）。

### 4.6 其它操作

- 双击卡片，或焦点在卡片上按 Enter：打开抽屉。
- 右键卡片：任务右键菜单（与任务树相同）。
- ↑ / ↓ 在卡片间按阅读顺序移动焦点并选中（托盘在前，其后 P1–P4）；空格切换当前卡片的选中状态。
- 焦点在卡片上按 Delete / Backspace：多选 → 批量删除确认；单选 → 删除确认（与任务树一致）。
- 不支持在象限内手动排序：优先级视图不承载顺序语义。

### 4.7 状态归属

负责人筛选、显示已完成、各象限排序、托盘折叠都是临时 UI 状态：不进项目文件、不进撤销栈，切换项目时重置。

### 4.8 与抽屉草稿同步

- 抽屉打开期间，若该任务的优先级被拖拽或菜单改变：同步更新抽屉的 `before` 与草稿（一次性信号，同 `renameRequest` 模式），避免抽屉显示旧值，或保存时把新值覆盖回旧值。
- 四象限视图下打开抽屉不触达甘特画布的定位，任务视图的滚动位置保持不变。

## 5. 视觉规范（§5）

### 5.1 颜色

新增四个语义 token（RGB 三元组，DOM 与 Canvas 共用同一来源）：

| token                | 亮色          | 暗色          |
| -------------------- | ------------- | ------------- |
| `--color-priority-1` | `220 38 38`   | `248 113 113` |
| `--color-priority-2` | `22 163 74`   | `74 222 128`  |
| `--color-priority-3` | `217 119 6`   | `251 191 36`  |
| `--color-priority-4` | `100 116 139` | `148 163 184` |

### 5.2 象限

- 容器：圆角 12，1px `border`，底色 `bg-elevated`。
- 标题带（34px）：象限色 8% 底色、左侧 3px 象限色强调条、下边 1px 象限色 20%。内容依次为 P 标签（象限色 16% 底 + 象限色文字）、名称（12px / 600）、行动提示（11px muted，可截断）、计数胶囊、排序按钮。
- 拖拽悬停：2px 象限色内描边 + 象限色 7% 底色。
- 空象限：虚线占位"拖拽任务到这里 / 设为 P1 紧急且重要"。

### 5.3 卡片（紧凑单行，28px）

从左到右：3px 任务色条（无自定义色用 `--color-task-bar`）→ 里程碑 `◆`（`text-warning`）→ WBS（11px muted，等宽数字）→ 名称（12px / 500，截断）→ 日期提示（11px）→ 负责人头像（18px 圆形首字，姓名哈希配色，与资源视图一致；最多 2 个，其余显示 `+N`）。

底边 2px 进度条：轨道为 `border` 70%，填充为自定义任务色 × 0.8，无自定义色时用 `--color-task-progress`。里程碑与进度为 0 时不画。

### 5.4 状态

- 悬停：只改边框色（零位移原则）。
- 选中：`bg` 底色 + 1px `primary` 60% 内描边；锚点再加 2px `primary` 内描边。
- 拖拽中：源卡片 40% 不透明度。
- 已完成（开启显示时）：55% 不透明度。

### 5.5 托盘

- 头部（32px）：收件箱图标 +「待分级」+ 计数 + 提示"拖到下方象限完成分级" + 折叠按钮。
- 内容：自适应网格（列宽不小于 230px），最大高度为矩阵区的 34%，超出后滚动。
- 托盘为空：只剩头部一行，提示改为"全部已分级 · 把卡片拖到这里可取消分级"，仍可接收拖回。

### 5.6 轴标签

11px muted，字距 0.08em；上方一行高 22px，左侧一列宽 26px、竖排。

## 6. 边界情形（§6）

- **值没变**（同象限内松手、菜单选了当前值、抽屉保存但优先级未改）：不产生命令与撤销记录。
- **撤销 / 重做**：卡片立即回到原桶。
- **远端同步替换文件**：矩阵按新文件重算；选中的任务已不存在时由现有选择逻辑处理。
- **摘要任务**：不进矩阵；抽屉与右键菜单不提供设置。
- **筛选后所有桶为空**：象限显示"没有匹配的任务"。项目本身零任务：矩阵区显示空状态，引导使用任务树的「新建任务」。
- **折叠的祖先**：不影响矩阵，矩阵不依赖折叠状态。
- **切换视图**：矩阵的筛选与排序保留。**切换项目**：重置。
- **手改文件里的越界值**（0、5、`"high"`）：加载时丢弃，视为未分级。
- **版本兼容**：旧版前端或服务端会静默剥离 `priority`，所以发版必须先服务端、后前端（§10）。

## 7. 实施阶段（§7）

1. **PR 1 `feat(schema,server)`：优先级字段全链路，无界面改动。** schema / 类型 / normalize / 草稿合并白名单 / MCP 契约 / 服务端白名单与查询 / CSV。可独立合并并先行部署服务端。

3. **PR 3 `feat(web)`：四象限视图。** `ViewMode`、布局分支、工具栏入口、矩阵组件、纯函数、选择联动、拖拽。

## 8. 测试（§8）

### 8.1 单元

- schema：接受 1–4；拒绝 0、5、字符串；`normalizeFile` 丢弃越界值；**经 `normalizeFile` 往返后 `priority` 仍在**（防静默剥离的回归）。
- api-contract：`create` / `update`（含 `null` 清除）/ `search` 的 `priority` 校验。
- domain：`updateTaskFromDraft` 携带优先级的新设与清除。
- server：`updateTask` 白名单、`applyCreateToFileSync`、`searchTasksInFile` 过滤与 `TaskSummary.priority`。
- web：分桶、排序、日期提示、落点判定、`revealTask` 的纵向定位选项等纯函数。

### 8.2 E2E

`priority-marks.spec.ts` 覆盖 §3（任务树 P 标签、抽屉分段控件、右键二级页、画布悬浮提示）；`priority-matrix.spec.ts` 覆盖 §4：

## 10. Coding Agent 实施注意事项

**字段白名单（漏任何一处都是静默丢数据，不会报错）：**

1. `packages/schema/schema.json` 的 `$defs.task.properties`。`stripUnknownFields` 按 schema 驱动，登记后各加载路径自动放行。
2. `packages/domain/src/commands.ts` 的 `TASK_DRAFT_FIELDS`——否则抽屉保存会丢掉优先级修改。
3. `apps/web/src/components/TaskDrawer.tsx` 的 `tasksEqual` 键表——否则只改优先级时保存按钮不亮。
4. `packages/api-contract/src/mcp.ts` 与 `apps/server/src/modules/projects/service.ts` 的逐字段白名单。

不需要改动：数据库迁移（任务整体存放在 `projects.file_jsonb`）、IndexedDB 版本、撤销栈、复制粘贴、通用 `/commands` 端点。

**发版顺序：先服务端，后前端。** 旧服务端在 PUT 时会剥离它不认识的字段，带界面的前端先上线会让用户标的优先级在保存并刷新后消失。

**交互与结构：**

- 「新建任务」按钮位于 `TaskTable` 的搜索栏，不在工具栏。
- 抽屉草稿不是实时的，处理见 §4.8。
- `BatchDeleteConfirm` 与 `DeleteTaskConfirm` 的挂载方式见 `TaskTable.tsx`。
- `revealTask` 原先只会读 `[data-gantt-chart]` 的尺寸，找不到就按 800×600 假定。现在多了 `horizontal: false` 选项（不改横向滚动），并在没有画布时退而测量任务树的滚动区 `[data-task-scroll]`。四象限里的定位一律走 `revealTask(id, { skipIfVisible: true, horizontal: false })`。
- `lib/setTaskPriority.ts` 是"在抽屉之外改优先级"的唯一入口（拖拽与右键菜单都走它）：同值不派发，并发出抽屉同步信号。新增写入口时不要绕开它。
- `Array.prototype.find` 会以 `undefined` 访问数组空洞（`filter`、`map` 则跳过空洞）。右键菜单的菜单项引用按序号存放在数组里，插入菜单项后序号必须连续，判空要同时判 `null` 和 `undefined`——否则菜单一关闭，"聚焦第一个可用项"的逻辑就会抛错、整页白屏（本次踩到）。

**测试约束：**

- 卡片不能使用 `role="row"`（多个任务视图用例按它选取）；新组件不能使用 `<aside>`（它是抽屉的定位符）。
- 右键菜单新增文案不能包含"删除 / 复制 / 剪切 / 粘贴 / 重命名"子串（`context-menu-hints.spec.ts` 用非精确匹配）。
- Playwright 的 `page.dragAndDrop()` 不触发原生拖拽，e2e 用合成 `DragEvent`；每次重绘后要重新查询节点。逐步鼠标事件（`mouse.move` → `down` → `move` → `up`）在 Chromium 里能触发原生拖拽，适合补测真实路径。
- 改了共享契约后跑全仓 `pnpm -r test`；e2e 需要 `VITE_E2E=1` 构建；服务端集成测试需要显式 `TEST_DATABASE_URL`。
