# ganttly v0.9.0 — GitHub 登录白名单

> v0.8.1 之后的功能版:服务端实例可用环境变量把 GitHub 登录限制到指定用户——白名单之外的人无法再登录官方实例,有自建需求的用户可按文档自行部署。

## 新功能:登录白名单 `ALLOWED_GITHUB_USER_IDS`(#19)

此前任何 GitHub 账号完成 OAuth 即可在服务端实例上自动获得个人工作区。现在可配置逗号分隔的 GitHub **数字 ID** 白名单:

```bash
# 查某用户的数字 ID(看返回 JSON 的 "id" 字段):
curl https://api.github.com/users/<github用户名>

# .env
ALLOWED_GITHUB_USER_IDS=12345678,87654321
```

| 行为           | 说明                                                                                                                            |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| **仅数字 ID**  | 按稳定的 GitHub 数字 ID 匹配,不按可修改的用户名                                                                                 |
| **拒绝即无痕** | 名单外用户登录时被重定向回 Web 并提示「仅允许白名单内的用户登录」,数据库零落库(无用户、无工作区、无会话),服务端日志记录被拒账号 |
| **启动即校验** | 配置含非数字条目会直接启动失败(fail-fast),防止笔误把所有人挡在门外                                                              |
| **未配置不变** | 留空 = 开放登录,与旧版本行为一致;自建实例升级完全兼容                                                                           |

**注意:白名单只拦截新登录。** 启用前已登录的用户,会话 Cookie 最长 7 天自然失效;但开放期内创建的 PAT(MCP 令牌)不会自动过期——启用后请按 ops-runbook 新增的「登录白名单启用审计」一节核对存量用户并吊销陌生账号的 PAT。

## 一并改进

- **登录失败原因可见**:服务端通过 `?login_error=` 带回的失败码此前在 Web 端无任何展示,现已打通——登录失败页与登录卡会显示具体原因(白名单拒绝 / GitHub 登录失败可重试 / 开发模式提示),不再是静默失败

## 升级与文档

- 自建实例:`git pull && docker compose up -d --build`,不需要任何迁移;需要限制登录时参考 self-hosting 文档新增的「限制可登录用户(白名单)」小节
- 设计文档 §8.2 登录流程、§14.2 环境变量清单已同步
