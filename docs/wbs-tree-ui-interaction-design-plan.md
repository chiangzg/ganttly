# WBS 任务树 UI 与交互优化设计计划

| 字段     | 内容                                                          |
| -------- | ------------------------------------------------------------- |
| 文档状态 | Implemented(2026-08-20,见 §11 实施差异)                       |
| 适用范围 | 编辑器左侧任务列表(WBS 任务树)                                |
| 目标     | 提升可读性、降低误操作、保持左栏紧凑                          |
| 关联实现 | `apps/web/src/components/TaskTable.tsx`、任务行拖拽、任务抽屉 |

## 1. 设计结论

WBS 列不再作为一段纯文本渲染，而是作为紧凑的树导航控件渲染。树控件由固定的拖拽槽、展开槽、层级引导和 WBS 编号组成；任务名称列优先吸收剩余宽度。

任务行只保留一种稳定的主语义：

- 单击任务行：选中任务。
- 双击任务行：打开任务详情抽屉。
- `F2` 或 `Enter`：重命名当前选中任务。
- 右键菜单：显式提供“重命名”和“编辑详情”。
- 展开按钮和拖拽槽：只执行各自的树操作，不触发行选择或详情打开。

这样可以消除“名字双击重命名、空白双击打开抽屉”的隐藏分区规则，也不会为了展示树信息继续扩大左侧面板。

## 2. 当前问题与原因

### 2.1 WBS 看起来像纯文本

当前 WBS 单元格同时承载缩进、拖拽图标、展开按钮和编号，但父任务与叶子任务主要依靠缩进和编号区分。任务全部展开时，用户需要逐行读取才能判断哪些任务仍可展开。

### 2.2 Hover 拖拽图标造成横向位移

当前任务行本身设置了 `draggable`，拖拽图标在 hover 时插入 WBS 单元格布局。图标出现会改变内容流，导致展开按钮和 WBS 编号向右移动；用户将鼠标移向展开按钮时，目标位置又发生变化。

### 2.3 双击命中区域不一致

当前双击逻辑根据 `closest('[data-field]')` 判断目标单元格：任务名进入行内编辑，WBS、空白区域等位置打开抽屉。用户必须记忆不可见的像素边界，实际操作容易误判为 bug。

### 2.4 直接增加 WBS 宽度不是正确解法

深层任务会增加缩进和编号长度。如果通过动态扩大 WBS 列来保证完整显示，任务名称列会被挤压，列表整体变得更难扫描。应将 WBS 设计成固定宽度的导航轨道，深层编号以省略号和 Tooltip 处理。

## 3. 视觉设计规范

### 3.1 WBS 单元格结构

每一行使用稳定的四段结构，所有行都保留相同槽位：

```text
层级缩进 | 拖拽槽 20px | 展开槽 18px | WBS 编号
```

- 拖拽槽始终占位；图标使用 `GripVertical`，默认低透明度，hover/focus 时提高透明度。
- 展开槽始终占位；父任务显示 `ChevronRight` / `ChevronDown`，叶子任务显示空槽。
- 层级缩进每级 `12px`，不要使用目前偏大的 `16px`。
- WBS 编号使用 `10~11px` 等宽字体、tabular-nums 和 muted 颜色。
- 图标出现或隐藏只能改变 `opacity`，不能改变 `display`、宽度或 padding。

### 3.2 父任务与叶子任务

父任务不能只靠颜色区分，至少使用三种信号：

- 有明确的展开/收起按钮。
- 任务名称使用半粗字重。
- 任务名称右侧显示紧凑的子任务计数，例如 `4 项`。

可选的轻量增强：父任务使用极淡的 `bg-bg` 或左侧 2px 边线；叶子任务保持普通背景和字重。颜色不能成为唯一语义来源。

建议示意：

```text
▾ 4       业务                 4 项
· 4.1     业绩同比
· 4.2     方案验证
```

### 3.3 层级引导线

在缩进区域绘制 1px 的浅色竖线和必要的分支横线，帮助用户沿树向下阅读。引导线只承担辅助阅读作用，不使用强边框，也不绘制覆盖整行的复杂连接图。

### 3.4 选中、Hover 和拖拽状态

- Hover：整行使用极浅背景；拖拽槽和详情按钮提高可见度。
- 选中：使用现有选中色和 1px inset ring，不能依赖粗重背景。
- 父任务选中：保留父任务的半粗字重和子任务计数。
- 拖拽源：整行降低透明度，但 WBS 结构槽仍保持可辨识。
- 拖拽目标：`before/after` 使用 2px 插入线；`inside` 使用整行浅色高亮。

## 4. 紧凑布局参数

默认任务面板目标宽度为 `400~420px`，不再因为深层 WBS 自动无限扩张。推荐默认列宽：

| 列         |         默认宽度 | 说明                                 |
| ---------- | ---------------: | ------------------------------------ |
| WBS 树控件 |           `96px` | 固定；包含缩进、拖拽槽、展开槽和编号 |
| 任务名称   | `minmax(0, 1fr)` | 吸收剩余宽度，允许省略号             |
| 工期       |           `52px` | 保留现有列功能                       |
| 人天       |           `52px` | 保留现有列功能                       |
| 进度       |           `48px` | 保留百分比和进度色                   |
| 详情入口   |           `28px` | 固定槽，hover/focus 显示图标         |

实现约束：

- WBS 列设置上限 `112px`；超过上限的深层 WBS 编号使用 ellipsis。
- 完整 WBS 编号通过 `title` 或 Radix Tooltip 提供。
- 任务名称最小宽度不低于 `140px`；面板继续缩小时优先压缩 WBS 与数值列，而不是让名称列消失。
- 用户可拖拽任务面板边界调整宽度，偏好继续保存在现有 layout preferences 中。
- 表头和每一行必须复用同一个 `gridTemplateColumns`，避免列错位。

## 5. 交互规范

### 5.1 行点击与双击

事件优先级固定如下：

1. 展开按钮、拖拽槽、详情按钮、输入框等明确控件先消费事件。
2. 其他区域单击只执行选择。
3. 其他区域双击统一打开详情抽屉。

双击不再按任务名、WBS、工期或空白区域分流。这样用户在整行任意位置执行同一个动作都会得到同一个结果。

### 5.2 重命名

重命名不再依赖双击任务名：

- `F2`：对当前选中任务进入名称编辑。
- `Enter`：在任务行获得焦点且未处于编辑状态时进入名称编辑。
- 右键菜单“重命名”：进入名称编辑。
- 编辑中的 `Enter` 提交，`Escape` 取消，失焦提交，沿用现有命令和 undo 语义。

名称列 hover 时可以显示一个固定槽位的铅笔图标，但图标只作为可发现性增强，不改变主交互规则。

### 5.3 展开与收起

- 只有点击 Chevron 才展开/收起。
- Chevron 的点击必须 `stopPropagation()`，不改变选中任务，不打开抽屉。
- 父任务使用 `aria-expanded`；叶子任务不渲染可点击的伪展开按钮。
- 保留左右方向键展开/收起能力。
- 在任务表工具栏增加“全部展开 / 全部收起”入口，作为批量导航操作，不影响任务数据 undo 栈。

### 5.4 拖拽排序

- 移除行级 `draggable`。
- 仅拖拽槽启动 HTML5 DnD；拖拽槽之外的行区域不显示 grab 光标。
- 拖拽槽点击不触发行选择；拖拽结束后保持原选中任务。
- 继续使用 `before | inside | after` 三种落点。
- 靠近列表顶部或底部自动滚动，`Escape` 取消拖拽。
- 禁止拖入自身或自身后代。
- 一次拖拽继续对应一条 `moveTaskWithRollupCommand` undo 记录。

### 5.5 详情入口

在任务行末尾保留一个固定宽度的详情槽，使用 `PanelRight` 或 `ArrowUpRight` 图标：

- 默认不可见但占位；hover/focus 时显示。
- 点击后打开抽屉。
- Tooltip 文案为“打开任务详情”。
- 该按钮是双击之外的显式入口，解决新用户不知道如何打开抽屉的问题。

## 6. 可访问性与语义

- 任务列表使用 `role="treegrid"`，任务行使用 `role="row"`。
- 每行设置 `aria-level`、`aria-posinset`、`aria-setsize`。
- 父任务设置 `aria-expanded`。
- 拖拽槽设置明确的 `aria-label="拖动任务"`，详情按钮设置 `aria-label="打开任务详情"`。
- 图标按钮必须可通过键盘聚焦，并提供 Tooltip 或可访问名称。
- 颜色变化不能是父子状态、选中状态或拖拽状态的唯一表达。

## 7. 实现拆分

### P0：先修正行为边界

1. 在 `TaskTable.tsx` 中移除行级 `draggable`，新增独立拖拽槽。
2. 将双击逻辑统一为打开抽屉，保留名称编辑的 F2/Enter/右键入口。
3. 给拖拽槽、Chevron、详情按钮加事件隔离。
4. 保留现有 `before/inside/after` 目标计算和命令模型。

### P1：完成树表视觉层级

1. 抽取 `TaskTreeCell` 或等价的展示组件，统一渲染缩进、引导线、拖拽槽、展开槽和 WBS 编号。
2. 增加父任务子任务计数和轻量 summary 样式。
3. 固定 WBS 列上限，深层编号使用 ellipsis + Tooltip。
4. 增加固定详情槽，避免通过点击空白区域猜测抽屉入口。

### P2：完善可发现性与批量操作

1. 增加全部展开/全部收起。
2. 增加任务树 ARIA 属性和键盘焦点样式。
3. 统一任务行、画布任务条、资源视图的详情打开语义。
4. 在首次使用或空状态中提供一次性轻量提示，不在常态界面堆叠说明文字。

## 8. 测试与验收标准

### 8.1 视觉验收

- 鼠标从任务名称移动到 Chevron 时，WBS 编号和 Chevron 的 `x` 坐标不发生变化。
- 父任务和叶子任务在全部展开时无需逐个读取 WBS 即可区分。
- 默认面板宽度约 `400~420px` 时，任务名称仍可显示至少 140px。
- 五层嵌套不会撑大 WBS 列；完整编号可通过 Tooltip 查看。
- 亮色和暗色主题下，选中、父任务、拖拽目标都保持足够对比度。

### 8.2 交互验收

- 点击 Chevron 只展开/收起，不选中任务，不打开抽屉。
- 点击拖拽槽可以排序；点击同一行其他区域不会意外启动拖拽。
- 双击任务名、WBS、工期和空白区域都打开同一个详情抽屉。
- `F2`、`Enter` 和右键“重命名”进入同一个名称编辑器。
- 编辑状态下 `Enter` 提交，`Escape` 取消，且 undo 记录保持现有语义。
- `before/inside/after`、非法后代拖拽、Escape 取消和自动滚动全部回归通过。

### 8.3 建议新增或更新的 E2E

- `wbs-layout.spec.ts`：验证 hover 前后布局稳定、父子样式和深层编号 Tooltip。
- `wbs-interaction.spec.ts`：验证 Chevron、拖拽槽、详情按钮的事件隔离。
- 更新 `inline-edit.spec.ts`：移除“双击名称编辑”的依赖，改测 F2/Enter/右键重命名。
- 更新 `drawer-transaction.spec.ts`：双击任意任务行区域均可打开抽屉。
- 保留并扩展 `task-row-drag.spec.ts`：拖拽源改为拖拽槽，验证行主体不再可拖动。

## 9. 明确不做的事情

- 不把所有 WBS 编号改成彩色标签；这会增加视觉噪声。
- 不通过持续增加缩进来解决层级识别问题。
- 不保留“不同单元格双击执行不同命令”的隐式规则。
- 不让拖拽图标覆盖 Chevron 或通过 hover 改变网格尺寸。
- 不改变任务数据模型、WBS 编号生成规则和现有移动命令的持久化格式。

## 10. 成功标准

用户可以在不记忆隐藏热区的情况下完成以下操作：

1. 一眼看出哪些行是父任务、哪些行是叶子任务。
2. 点击 Chevron 展开/收起，不被拖拽控件干扰。
3. 从固定拖拽槽移动任务，不担心误触发选择或详情。
4. 双击任务行的任意普通区域都得到一致的详情结果。
5. 在约 `400~420px` 的左侧面板中，任务树仍保持清晰、紧凑和可扫描。

## 11. 实施差异(2026-08-20 实际落地版本)

实施时以本文档为基础做了两处结构性调整,并吸收/拒绝了部分条目:

**结构性调整**

1. **树形结构移入任务名列,而非留在 WBS 列**(§3.1 调整):WBS 列扁平化
   为 `[把手槽 18px][编号]`,所有深度的编号在同一 x 起点垂直对齐
   (`tabular-nums`,类似表格行号列);每级 16px 缩进参考线 + 常驻箭头槽
   渲染在任务名列(VSCode / MS Project / GanttPRO 惯例)。扁平编号下
   §2.4 的"深层编号撑宽列"问题不复存在,§4 的固定 96px/112px 上限与
   省略号 + Tooltip 机制不再需要,列宽按最长编号自适应。
2. **列宽体系不翻修**:工期/人天/进度列宽与面板默认宽度保持现状
   (§4 的 52/52/48 与 400~420px 面板未采纳),避免截断本地化内容与
   动存量用户偏好;基线偏差列不受影响。

**采纳**

- 子任务计数徽标:折叠的父任务名右侧显示「N 项」(§3.2),展开时不显示。
- 仅把手可拖拽:移除整行 `draggable`,DnD 仅从把手槽发起(§5.4);行内
  文本选择随之恢复。
- treegrid ARIA:`role="treegrid"` + 行 `aria-level` / `aria-expanded`
  (§6;`aria-posinset`/`setsize` 需改 flatten 数据流,未做)。
- 全部展开/收起:搜索栏两个图标按钮(§5.3);经直连 `setState` 写
  `collapsedTaskIds`,不进 undo 栈。
- 零位移验收(§8.1 首条)落地为 e2e 回归:`wbs-tree-layout.spec.ts` 断言
  hover 前后编号与箭头 boundingBox 不变。

**拒绝(与现状冲突或收益不足)**

- `Enter` = 重命名(§5.2):与既有 `Enter` = 新建同级任务冲突,保留
  原行为;重命名入口为 F2 / 右键菜单「重命名」/ 抽屉。
- 行尾 28px 详情槽(§5.5):双击已统一为开详情,不再额外占列。
- 名称列 hover 铅笔图标(§5.2 可选项):右键菜单已带 F2 提示,不加。

**其余 §5 交互规则(统一双击=开详情、Chevron 事件隔离、before/inside/after
落点、单条 undo 记录)按原文落地。**
